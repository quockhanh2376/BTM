# Orca (stablyai/orca) – đối chiếu với BTM

Cheki đọc ngày 2026-11-11, commit fce98d7, chỉ đọc mã nguồn và tài liệu, không chạy thử.

**Orca là gì:** app desktop Electron, có kèm app mobile, dùng để chạy nhiều agent song song (Claude, Codex, agy, Cursor, Grok…). Mỗi agent làm trong một git worktree riêng. Orca có chat/terminal, xem diff, trình duyệt, CLI để agent tự điều phối agent khác, lịch tự động, và theo dõi hạn mức.

**Khác BTM về gốc:**
- Orca là IDE cho một người ngồi điều khiển nhiều agent cùng lúc.
- BTM là dây chuyền PM → Dev → QC → Audit có luật cứng, chạy trên VM, các agent cách ly bằng user Linux riêng.
- Orca chạy mọi agent dưới cùng một user. Về bảo mật BTM chặt hơn, không nên lùi.

## Để sau

- **Kho tài khoản agy nhiều tài khoản** (Orca có `native-account-store`, lưu credential trong secret store của hệ điều hành và chọn tài khoản đang dùng). Khớp với ý anh sao lưu JSON; khi làm thì học cách Orca ghi file nguyên tử và dùng quyền riêng tư. Lưu ý: tự xoay vòng tài khoản để lách hạn mức có thể vi phạm điều khoản; BTM đang để `auto_switch_accounts: false`.
- **Lịch tự động có precheck** (cron + lệnh kiểm trước khi chạy). BTM đang cố ý để `auto_schedule: false`.
- **Chạy song song nhiều agent / nhiều worktree.** Là v2.0 của BTM, cần khoá theo agent và theo project.
- **Đưa lỗi CI và comment PR về lại agent để sửa.**
- **Điều khiển agent bằng ACP (Agent Client Protocol)** thay cho `-p` text: có sự kiện có cấu trúc (lượt xong, lý do dừng, xin quyền). Cần kiểm từng CLI có hỗ trợ ACP không trước khi tính.

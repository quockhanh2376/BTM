# BTM v1.0 – Kế hoạch 1: Lõi điều phối (CLI) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
>
> **Cách chạy ở dự án này:** Cheki (Claude, điều phối) giao từng task cho **Victor** (agy, code) rồi **Qeen** (codex, review read-only). Victor/Qeen không commit; Cheki kiểm tra diff, commit, push. Bước "Commit" trong task = việc của Cheki.

**Goal:** Lệnh `btm` chạy được một phiên thật trên project "Go to the Moon": PM tách task → Dev làm → gate tự động → QC chấm → dừng đúng luật.

**Architecture:** Node.js + TypeScript, không server (dashboard, systemd, Energy, Tài khoản để Kế hoạch 2–3). Core gọi 3 CLI qua `child_process`, mỗi lượt một process group có timeout. SQLite (`better-sqlite3`) giữ sổ vận hành; nội dung (task, báo cáo) nằm trong Git của project. Mọi luật cứng (lượt, timeout, scope, coder≠QC, vòng sửa) do code kiểm tra; Runner được inject để test bằng runner giả.

**Tech Stack:** Node 22, TypeScript (strict, ESM), tsx, vitest, zod, yaml, better-sqlite3.

**Spec:** `docs/spec.md` + `btm.config.yaml`

**Ngoài phạm vi Kế hoạch 1:** dashboard/Fastify/SSE, systemd, đọc hạn mức (Energy), trang Tài khoản, OpenSpec init, hàng đợi lệnh trực tiếp, nút Dừng khẩn cấp (Kế hoạch 1 dừng bằng Ctrl-C → kill process group).

## Global Constraints

- Không API key: có bất kỳ biến trong `login.forbidden_env` → `btm` từ chối chạy, exit code 2.
- `session.auto_schedule` và `rules.auto_switch_accounts` chỉ được là `false` (schema dùng `z.literal(false)`).
- Không bao giờ truyền `--dangerously-skip-permissions` cho agy (có test khẳng định).
- `turn.max_parallel_agents` = 1: Core chạy tuần tự, không có hai process agent cùng lúc.
- Agent không commit, không push. Core commit sau mỗi lượt Dev với author = agent đang ngồi ghế Dev: name = id agent (`jacky`), email = `<id>@btm.local`.
- Quyết định lệch spec §7 (theo yêu cầu anh Zon: báo cáo tối giản): kết quả QC là một JSON `{verdict, bugs, fix, confirm}` thay vì chấm từng tiêu chí; báo cáo Dev chỉ Bug / Cần sửa / Cần xác nhận.
- Mọi thao tác chỉ trong project active (`host.projects_root/<tên>`); đường dẫn ngoài `projects_root` → từ chối.
- Báo cáo agent tối giản: chỉ Bug / Cần sửa / Cần xác nhận (mẫu `team/templates/report.md`).
- Toàn bộ code ESM, `"type": "module"`, test bằng `npx vitest run`.

## Review Focus

1. **Dev sửa/xóa/đổi tên file ngoài scope, hoặc scope chứa `../`** → gate phải bắt cả file bị xóa và cả hai đường dẫn của rename; card có `..` hoặc đường dẫn tuyệt đối bị từ chối. (Task 3, Task 6)
2. **Agent treo và đẻ process con** → hết timeout phải kill cả process group, không để process con sống. (Task 5)
3. **Dev báo "OK" nhưng không đổi gì** → diff rỗng là gate rớt, không tới QC. (Task 6)
4. **QC trả lời không phải JSON hợp lệ / lẫn văn xuôi** → coi là `fail` với lý do `qc_output_invalid`, không crash, không bao giờ coi là pass. (Task 7)
5. **Hết lượt giữa chừng** (tổng hoặc theo ghế) → phiên dừng `out_of_turns`, không gọi thêm agent nào, giữ lượt dự phòng cho PM. (Task 8)

### Task 5: Runner

export interface ProcResult { exitCode: number | null; timedOut: boolean; durationMs: number; output: string }

argv theo tool (giá trị cố định, đã chạy thử thật 2026-11-08):

### Task 8: Điều phối phiên

**Files:** Create `src/core/prompts.ts`, `src/core/session.ts`, `tests/session.test.ts`

**Interfaces — Consumes:** `Config`, `Store`, `Runner`, `loadTaskCards`, `runGate`, `commitAll`, `headSha`, `parseQcResult`, `checkForbiddenEnv`.
**Produces:**
```ts
export function pmPrompt(goals: string[]): string;
export function devPrompt(card: TaskCard, fixNotes: string[]): string;
export function qcPrompt(card: TaskCard, base: string): string;
export type TaskState = 'pending' | 'passed' | 'failed' | 'blocked';
export interface SessionOutcome { status: 'done' | 'awaiting_approval' | 'needs_owner' | 'out_of_turns' | 'refused';
  sessionId: number | null; tasks: Record<string, TaskState>; notes: string[] }
export interface SessionDeps { cfg: Config; store: Store; runner: Runner; repo: string; env: NodeJS.ProcessEnv }
export function runSession(d: SessionDeps, goals: string[], o: { approved: boolean }): Promise<SessionOutcome>;
```
Luồng (mỗi lượt: `startTurn` → runner → `endTurn`):
1. `checkForbiddenEnv` vi phạm, hoặc `repo` không nằm trong `host.projects_root`, hoặc `goals.length` ∉ [1, `max_goals`] → `refused` (không tạo session).
2. Tạo session; checkout nhánh `session/<id>` từ `main`.
3. Lượt PM với `pmPrompt` (ghi thẻ vào `team/tasks/`, không sửa gì khác). Core `commitAll` với author PM. Thẻ lỗi (`CardError`) → `needs_owner`.
4. `require_task_approval` và `!o.approved` → `awaiting_approval` (dừng, thẻ đã commit để anh xem).
5. Với từng thẻ: `base=headSha`; lượt Dev → `commitAll` (author ghế dev) → `runGate`. Rớt → `recordHandoffFailure` mỗi lý do, lý do thành `fixNotes`, Dev làm lại. Đạt → lượt QC (`qcPrompt`) → `parseQcResult`. `pass` → `passed`. `fail` → `bugs+fix` thành `fixNotes`, quay lại Dev. Số vòng sửa (gate rớt + QC rớt) > `max_fix_rounds` → task `failed`, phiên `needs_owner`.
6. Dev trả lời chứa `BLOCKED` → task `blocked`, phiên `needs_owner`.
7. Trước **mọi** lượt: nếu `countTurns` tổng ≥ `max_turns − reserve_turns_for_pm` (lượt không phải PM) hoặc theo ghế ≥ `max_turns_per_seat[seat]` → `out_of_turns`.
8. Agent ngồi ghế QC trùng agent đã code task (đổi ghế giữa chừng) → không gọi QC, `needs_owner` (luật `coder_cannot_qc_same_task`).
9. Lượt có `timedOut` hoặc exit ≠ 0 → `endTurn('timeout'|'error')`, `commitAll` WIP với message `WIP <id>: <lý do>`, `needs_owner`.
10. Hết thẻ → `done`; `setSessionStatus` luôn được gọi với status cuối.

Prompt: mỗi cái ≤ 6 dòng, tiếng Việt, kết thúc bằng định dạng trả lời (Dev: báo cáo vào `team/reports/<id>-dev.md` theo mẫu; QC: chỉ một JSON `QcResult`). Không yêu cầu agent commit.

- [ ] **Step 1: Test** — runner giả (`fakeRunner(script: Array<(cwd)=>Partial<TurnOutput>>)`) ghi file vào repo tạm thay agent:
  - `happy path`: PM ghi T-001 → Dev sửa file trong scope + report → QC trả `{"verdict":"pass",…}` → `done`, `tasks['T-001']==='passed'`, 3 lượt trong store, 2 commit trên `session/1`.
  - `awaiting approval`: `approved:false` → dừng sau PM, Dev không bị gọi.
  - `gate reject then fix`: lần 1 Dev sửa ngoài scope → lần 2 đúng → `passed`; `handoff_failures` có `out_of_scope:…`.
  - `fix rounds exhausted`: QC fail 3 lần với `max_fix_rounds: 2` → `failed`, `needs_owner`.
  - `out of turns`: `max_turns: 3` → dừng `out_of_turns`, runner không được gọi lần thứ 4.
  - `refused on API key`: env có `OPENAI_API_KEY` → `refused`, runner không được gọi.
  - `timeout makes WIP commit`: Dev trả `timedOut:true` sau khi sửa file → có commit `WIP T-001`, `needs_owner`.
  - `invalid QC output`: QC trả văn xuôi → coi là fail, Dev được gọi lại với note `qc_output_invalid`.
- [ ] **Step 2–4:** FAIL → implement → PASS. **Step 5:** Commit "feat: session".
